# 통신 데이터 기반 추천·운영 자동화 파이프라인

합성 통신 데이터를 생성하고 PostgreSQL에서 분석하기 좋은 형태로 가공하는 프로젝트입니다. 요금제·콘텐츠 사용량·선택 혜택·가족결합 데이터를 바탕으로, 고객별 요금제 추천과 운영 현황 분석에 필요한 데이터를 제공합니다.

실제 고객 정보나 청구 데이터를 사용하지 않습니다. 재현 가능한 합성 데이터를 사용해 데이터 처리와 추천 시나리오를 검토합니다.

## 어떤 데이터를 다루나요?

사용자와 가족, 요금제와 혜택, 할인 정책, 일별 콘텐츠 사용량을 다룹니다. 이 데이터를 두 가지 목적에 맞게 나눕니다.

| 영역 | 목적 | 제공하는 데이터 |
| --- | --- | --- |
| 운영 분석 | 전체 고객과 상품 이용 현황 파악 | 가입자·가족결합·서비스·할인 현황, 요금제·연령대·콘텐츠별 사용량 |
| 개인화 분석 | 고객별 요금제와 혜택 검토 | 고객 이름과 현재 요금제, 최근 사용량, 선택 서비스, 가족결합·할인 상태 |

운영 영역은 이름을 제외하고 사용자·가족 등의 연결 키를 가명화합니다. 개인화 영역은 고객별 조회를 위해 합성 이름과 원본 사용자 ID를 유지합니다.

## 어떻게 처리하나요?

```text
합성 데이터 생성
      ↓
원본 CSV 저장 (로컬 또는 S3)
      ↓
파이프라인 실행 → 임시 적재와 원본 품질 검사
      ↓
┌───────────────────┬────────────────────┐
│ 운영 DW → 운영 DM │ 개인화 DW → 개인화 DM │
└───────────────────┴────────────────────┘
      ↓
변환 결과 품질 검사 → 성공한 배치 저장
      ↓
영역별 조회 View → n8n 고정 쿼리 → AI 분석
```

DW는 목적별 상세 데이터를 저장하고, DM은 조회에 사용할 집계와 현재 상태를 제공합니다. 데이터베이스는 추천 판단에 필요한 데이터를 반환하며, 추천 분석은 외부 AI·n8n 워크플로에서 수행합니다.

로컬에서는 PowerShell로 실행합니다. AWS 배포에서는 한 Lambda가 S3 파일을 내려받아 같은 파이프라인으로 두 영역을 함께 처리합니다. 전체 배치, 증분 초기화, 날짜별 증분 적재와 원본 정정을 지원합니다.

## 어디부터 읽으면 되나요?

- 전체 설계를 이해하려면 [데이터 아키텍처](docs/architecture.md)를 읽습니다.
- 직접 실행하려면 [로컬 실행 가이드](docs/guides/local-run.md)를 따릅니다.
- AWS에 배포하려면 [AWS 배포 가이드](docs/guides/aws-deployment.md)를 읽습니다.
- CSV를 분석하거나 쿼리를 작성하려면 [원본 데이터 명세](docs/data/raw-data-schema.md)와 [n8n 쿼리 계약](docs/integration/n8n-fixed-query-contract.md)을 참고합니다.

생성 CSV와 가상환경, 인증 정보는 Git에서 제외합니다. 현재 실행에 필요한 코드·SQL·문서와 고정 쿼리 카탈로그를 관리하며, 로컬 과거 자료는 Git에서 제외된 `.local/archive/`에 보관합니다.
