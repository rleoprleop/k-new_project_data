# SQL execution

## 실행 순서

1. `db/schema/001~060`이 audit, 두 DW, 두 DM, AI View와 역할을 정의합니다.
2. `db/load/*staging*`이 CSV를 세션 임시 테이블로 읽습니다.
3. `db/quality/010_staging_full.sql` 또는 증분 검사가 원본 관계를 확인합니다.
4. 운영/개인화 DW 변환을 각각 수행합니다.
5. 운영/개인화 DM 변환과 품질 검사를 수행합니다.
6. 성공한 경우에만 워터마크와 `SUCCEEDED` 상태를 커밋합니다.

실제 실행은 사용자가 RDS 연결·비밀·S3 파일 준비를 완료한 뒤 수행합니다. 현재 저장소에는
실행 가능한 스크립트만 있으며 연결 문자열, DB 비밀번호, HMAC 키는 포함하지 않습니다.

## 기준일과 사용량 종료일

- 가입자 조건: `subscription_start_date <= reference_date`
- 처리 가능한 사용량: `min(오늘(KST)-1, 성공 워터마크)`까지
- 데이터 종료일 뒤에는 DB를 폐기한다는 전제이므로 별도 장기 stale 정책은 두지 않습니다.
- 원천 사용량은 가입 전 행도 그대로 사용합니다. 이 가정은 품질 실패 조건이 아닙니다.

## 재실행

입력 checksum이 이미 성공한 배치는 no-op입니다. 증분은 워터마크 다음 날짜부터 연속이어야
하고, 정정은 워터마크 이하 날짜만 허용합니다. 정정 시 해당 월의 영향 집계를 교체합니다.
