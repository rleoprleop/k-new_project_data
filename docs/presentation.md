# 합성 통신 데이터 파이프라인: 작업 범위와 주요 이슈

통신 고객의 요금제·콘텐츠 사용량·선택 혜택·가족결합 정보를 분석할 수 있도록
합성 데이터 생성부터 PostgreSQL 적재, 운영·개인화 조회 제공까지 구현했습니다.
이 문서는 발표에서 설명할 작업과 해결한 이슈를 요약합니다. 세부 규칙과 실행 방법은 연결된 문서를 기준으로 합니다.

## 1. 작업 범위

작업의 목표는 같은 원본에서 전체 고객의 운영 현황 분석과 고객별 요금제·혜택 검토를 지원하는 것입니다.
실제 고객 정보를 사용하지 않고, 관계와 정책 조건을 갖춘 합성 데이터로 처리 구조와 분석 사례를 구성했습니다.

구현 범위는 다음 흐름을 연결하는 것입니다.

```text
합성 데이터 생성 → 원본 CSV 저장 → staging 적재·검사
→ 운영·개인화 DW/DM → 결과 검증·실행 이력 → 조회 View·고정 쿼리
```

로컬 실행과 AWS Lambda 실행은 같은 SQL 파이프라인을 사용합니다.
DB는 분석에 필요한 데이터를 제공하고, 추천 판단과 설명은 외부 AI·n8n 워크플로에서 수행하도록 역할을 나눴습니다.

## 2. 주요 작업과 설명

### 합성 통신 데이터 생성

고객·가족·요금제·혜택·할인 정책·콘텐츠 사용량을 서로 연결되는 데이터로 생성했습니다.
난수 시드와 기준일로 재현성을 확보하고, 사용량에 비해 요금제가 높거나 낮은 고객 등 추천 검토 사례를 포함했습니다.
사용량은 단일 CSV 또는 날짜별 파일로 출력하며 생성 결과의 관계와 분포를 검사합니다.

상세: [생성기 안내](../generator/README.md), [생성 규칙](data/generation-spec.md), [원본 데이터 명세](data/raw-data-schema.md).

### 원본 저장과 운영·개인화 데이터 모델

원본 CSV는 로컬 또는 S3에 보존하고 staging에서 임시로 읽습니다.
DW는 목적별 데이터를 저장하며 DM은 일·월 집계와 현재 상태를 제공합니다.
운영 영역은 이름을 제외하고 연결 키를 가명화하며, 개인화 영역은 합성 이름·사용자 ID·상세 사용량을 유지합니다.

상세: [데이터 아키텍처](architecture.md), [DB 계층과 객체](../db/README.md).

### 전체·증분·정정 파이프라인

전체 적재, 고객·정책 기준 데이터 초기화, 날짜별 사용량 추가, 기존 날짜의 원본 정정을 지원합니다.
체크섬과 마지막 성공 날짜로 재실행을 제어하고, 실행 잠금과 트랜잭션으로 두 영역의 데이터 상태를 함께 관리합니다.
데이터 배치는 변환과 품질 검사를 모두 통과했을 때 커밋합니다.

상세: [파이프라인 안내](../pipeline/README.md), [로컬 실행 가이드](guides/local-run.md).

### 데이터 품질과 실행 결과 확인

원본의 관계·값, DW 변환 결과, DM 집계 결과를 검사하고 배치 실행 이력을 남깁니다.
적재 성공은 실행 종료 메시지뿐 아니라 배치의 `SUCCEEDED`, 품질 기록과 실패 건수,
증분 워터마크가 목표 날짜에 도달했는지를 함께 확인하도록 정리했습니다.

상세: [품질 검사와 실행](../db/README.md#실행과-검증), [적재 후 검증 도구](../tools/README.md#적재-후-검증).

### AWS 실행 환경

S3의 입력 파일을 Lambda에서 준비하고, Secrets Manager의 인증 정보와 가명화 키를 실행 환경에 전달합니다.
Lambda 컨테이너에 PowerShell과 PostgreSQL 클라이언트를 포함해 로컬 실행기를 재사용하며,
Docker·ECR·GitHub Actions로 실행 이미지를 관리합니다.

상세: [Lambda 구성](../deploy/README.md), [AWS 배포 가이드](guides/aws-deployment.md).

### 조회 계정과 고정 쿼리 제공

운영·개인화 조회 계정을 분리하고 해당 영역의 AI View와 공개 상품·혜택·할인 정책 마스터만 조회하도록 구성했습니다.
AI는 쿼리 ID와 파라미터를 선택하고 n8n은 등록된 고정 SQL을 실행합니다.
현재 운영 카탈로그는 분석 6개로 구성하며, 개인화는 고객별 사용량·혜택 검토를 위한 별도 카탈로그를 사용합니다.

상세: [n8n 조회 계약](integration/n8n-fixed-query-contract.md), [쿼리·뷰 명세](integration/view-schemas/README.md).

### 운영 쿼리 최적화와 비교 도구

월별 고객 사용량 통계의 집계·조인 순서를 개선하고 최종 SQL을 운영 카탈로그와 파이프라인에 반영했습니다.
원래·최종 SQL을 보존해 같은 조건에서 실행시간과 상세 실행계획을 비교할 수 있도록 도구를 정리했습니다.
추천 사례 고객을 찾는 SQL과 적재 결과 확인 도구도 함께 제공합니다.

상세: [최적화 이슈 기록](issues/operations-query-optimization.md), [쿼리 비교 도구](../tools/query-plans/README.md), [조회·검증 도구](../tools/README.md).

## 3. 주요 이슈와 해결 방법

| 이슈 | 발생 원인·영향 | 적용한 해결 방법 |
| --- | --- | --- |
| 가입일 이전 사용량 | 합성 원본에 가입 이전 날짜의 사용량이 있어 그대로 적재하면 분석 대상의 업무 정의와 맞지 않음 | 원본을 보존하고 두 DW에서 가입일 이후 사용량만 적재. 품질 검사도 같은 필터 기준으로 합계를 대조 |
| 연령 상한의 NULL | 정책에서 NULL은 상한 없음을 뜻하지만 기존 DW의 NOT NULL 제약과 충돌 | 070 마이그레이션으로 두 DW의 상한 NULL 허용. 상한이 있는 경우에만 하한 이상인지 검사 |
| `18.0` 형태의 정수 연령 | CSV의 소수 표기와 PostgreSQL integer 직접 입력 방식이 맞지 않음 | staging에서 numeric으로 읽고 정수·범위를 검사한 뒤 integer로 변환. 실제 소수 값은 거절하고 NULL은 유지 |
| 컨테이너에서 CSV 경로 처리 | 로컬과 Lambda의 파일 위치 차이로 기존 적재 경로를 그대로 사용할 수 없음 | psql 작업 디렉터리를 입력 위치로 맞추고 고정 파일명의 클라이언트 `\copy` 사용 |
| 공개 정책표의 조회 권한 | AI View만 허용한 계정에서는 분석에 필요한 공개 마스터를 직접 조회할 수 없음 | 080 마이그레이션으로 각 영역의 공개 마스터 8개만 허용. 고객·가족·사용량 기본 객체 조회와 쓰기는 계속 제한 |
| 월별 통계 쿼리의 집계 비용 | 카테고리 행을 차원과 조인한 뒤 가명 문자열로 고객·월 합계를 계산해 처리량이 커짐 | 월 키로 기간 제한 → 숫자 고객·월 키로 선집계 → 차원 조인 순서로 개선. 130 뷰와 운영 002·005에 반영 |

원본의 표기, 업무 의미, 저장 타입에 따라 해결 위치를 달리했습니다.
가입일 문제는 적재 대상의 필터, 상한 NULL은 영구 스키마 제약, 정수 표기는 staging 검증으로 처리했습니다.
쿼리 성능 문제는 데이터를 다시 저장하는 대신 일반 뷰와 조회 SQL의 처리 순서를 변경했습니다.

## 4. 쿼리 최적화 결과

사용자가 제공한 운영 조회 계정의 측정 로그에서, 같은 64MB 메모리·읽기 전용 스냅샷으로
워밍업 후 교대로 5회 측정한 실행시간 중앙값을 비교했습니다.

| 분석 | 6개월 실행시간 | 전체 기간 시간 감소율 |
| --- | --- | ---: |
| 월별 평균·중앙값 (`OPS_ANALYSIS_002`) | 1,231.185 → 689.453ms, 44.00% 감소 | 41.45% |
| 월별 분포·집중도 (`OPS_ANALYSIS_005`) | 1,620.354 → 1,075.564ms, 33.62% 감소 | 34.09% |

1개월·12개월 조건에서도 개선을 확인했습니다. 이 수치는 DB 실행시간이며 화면·네트워크까지 포함한 응답시간은 아닙니다.
측정 조건과 모든 기간의 결과는 [최적화 이슈 기록](issues/operations-query-optimization.md)에 있습니다.

## 5. 작업 결과

합성 데이터의 생성 규칙, 목적별 저장 모델, 증분·정정 처리, 품질 검사와 제한된 조회를 하나의 흐름으로 연결했습니다.
원본은 보존하면서 업무 규칙과 타입을 검증하고, 운영과 개인화의 정보 수준을 분리해 분석에 필요한 데이터를 제공합니다.
이 데이터 기반과 조회 도구를 통해 고객별 요금제·혜택 검토와 운영 현황 분석을 지원합니다.
