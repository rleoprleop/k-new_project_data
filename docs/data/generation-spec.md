# 합성 통신 데이터 생성 상세 사양

> 생성기 설치와 실행 방법은 [생성기 README](../../generator/README.md)를 참고하세요. 원본 CSV의 컬럼·관계·조인 방법은 [원본 데이터 스키마](raw-data-schema.md), 가명화 출력은 [분석용 데이터 스키마](analysis-data-schema.md)에 정리되어 있습니다.

KT 모바일 요금제, 사용량, 선택 혜택, 인터넷-모바일 결합 추천 로직을 검증하기 위한 합성 데이터 생성기입니다. 실제 개인정보나 실제 고객 청구 데이터를 사용하지 않습니다.

## 1. 생성 범위

기본 실행은 기준일 `2026-09-15`를 기준으로 사용자 1,000명과 직전 90일의 데이터를 생성합니다.

| 항목 | 기본값 | 설명 |
|---|---:|---|
| 사용자 수 | 1,000명 | 가족 소속 사용자와 독립 사용자 포함 |
| 사용 기간 | 90일 | 기준일 전날까지의 일별 사용량 |
| 난수 시드 | 3 | 같은 옵션이면 같은 결과 재현 |
| 의도적 비최적 요금제 비율 | 20% | 추천·이상치 탐지를 위한 테스트 사례 |
| 가족 소속 사용자 목표 비율 | 56% | 가족 구조 생성 단계의 합성 가정 |

생성기는 같은 실행에서 원본 성격의 합성 CSV와 가명화된 분석용 CSV를 각각 만듭니다.

- `generator/data/generated/`: 원본 성격의 합성 데이터. 내부 Raw 적재와 생성 검증용입니다.
- `generator/data/generated_analysis/`: 분석·추천 Feature 설계용 데이터입니다. 이름과 원본 키를 제외하고, 사용자·가족·결합 키를 HMAC 기반 분석 키로 바꿉니다.

`generator/data/generated/`는 로컬 개발 환경의 **Data Lake** 역할을 합니다. 파이프라인은 이 원본 CSV를 PostgreSQL `pg_temp.stg_*`에 임시 적재한 뒤 운영·개인화 DW·DM을 생성합니다. staging은 배치 트랜잭션 종료 시 삭제됩니다. `generator/data/generated_analysis/`는 별도 분석용 선택 출력이며 파이프라인 입력으로 사용하지 않습니다. 두 출력 디렉터리의 CSV는 재현 가능한 생성물이므로 Git에는 올리지 않습니다.

원본·분석용 출력의 논리 테이블은 다음 14개입니다. 원본의 기본 `single` 방식과 분석용 출력은 각각 CSV 14개를 만들며, 원본 `daily` 방식은 스냅샷 CSV 13개와 날짜별 `content_usage` 파티션을 만듭니다. `both` 방식은 단일 콘텐츠 파일과 날짜별 파티션을 함께 만듭니다.

```text
users, families, bundle_discount_compositions,
plans, age_benefits, plan_age_benefits,
additional_services, plan_benefits,
discounts, internet_bundle_discount_rules, premium_family_discount_rules,
user_discounts, user_services, content_usage
```

`daily_usage`와 `family_relationships`는 생성·검증에는 사용하지만 CSV로 내보내지 않습니다. 사용자별 예상 청구액과 잠재 할인액도 저장하지 않습니다.

분석용 출력에서는 다음 변환을 적용합니다.

| 원본 정보 | 분석용 출력 |
| --- | --- |
| `user_id`, `family_id`, `bundle_composition_id` | 안정적으로 조인 가능한 HMAC 기반 분석 키 |
| `name` | 제외 |
| `age` | `age_band` |
| `subscription_start_date` | `subscription_cohort`, `tenure_months` |
| 결합·할인·서비스의 `start_date`, `end_date` | `start_month`, `end_month` |
| 분석에 불필요한 행 식별자 | `content_usage_id`, `user_discount_id`, `user_service_id` 제외 |
| 콘텐츠 사용 이력 | 분석·추천 Feature 산출을 위해 가명 사용자 키와 `usage_date`를 유지 |

`generated_analysis/analysis_manifest.json`에는 행 수와 적용 변환이 기록됩니다. 기본 HMAC 키는 이 합성 데이터 전용입니다. 실데이터로 전환할 때는 `KT_ND_ANALYSIS_PSEUDONYMIZATION_KEY` 환경 변수 또는 `--analysis-pseudonymization-key` 인자로 비밀값을 반드시 전달해야 합니다.

## 2. 생성 기준과 합성 가정

실제 정책 기준과 합성 분포 가정을 구분해서 사용합니다.

- 요금제 가격·제공량, 연령 혜택, 인터넷 결합 구간, 프리미엄 가족결합 조건은 생성기 내부 정책 마스터에 정의합니다.
- 연령·직업·가족 형태·사용량·가입 여부의 확률은 실제 고객 원천 데이터가 아닌 추천 테스트용 합성 가정입니다.
- 선택약정 할인은 계산 범위에 포함하지 않습니다.
- 금액은 별도 표기가 없으면 부가세 포함 월 기준 원화입니다.

### 2.1 연령과 사용자

연령대의 기본 모양은 통계청 2026년 장래인구추계 값을 사용합니다. 다만 전체 인구와 이동통신 가입자의 연령 분포가 같지 않다고 보고 다음 보정을 적용합니다.

독립 사용자의 연령대 추출 가중치는 `2026년 추계인구 × 이동통신 가입 보정값`을 계산한 뒤 합계가 1이 되도록 정규화합니다.

| 연령대 | 추계인구(천 명) | 가입 보정값 | 생성 연령 범위 |
|---|---:|---:|---:|
| 0~9 | 2,775 | 0.12 | 8~9세 |
| 10~19 | 4,531 | 0.85 | 10~19세 |
| 20~29 | 5,888 | 1.05 | 20~29세 |
| 30~39 | 7,038 | 1.05 | 30~39세 |
| 40~49 | 7,624 | 1.05 | 40~49세 |
| 50~59 | 8,587 | 1.00 | 50~59세 |
| 60~69 | 7,980 | 0.95 | 60~69세 |
| 70~79 | 4,665 | 0.85 | 70~79세 |
| 80+ | 2,522 | 0.65 | 80~90세 |

- 0~9세는 이동통신 가입 비율을 낮게 반영하며 실제 생성 연령은 8세부터 시작합니다.
- 10~69세는 인구 분포 형태를 대체로 유지합니다.
- 70세 이상은 이동통신 가입 보정값을 낮춰 적용합니다.
- 독립 사용자는 보정된 연령 확률로 생성하고, 가족 사용자는 부모·자녀 등의 최소 연령 차이가 성립하도록 생성합니다.
- 이름은 `Faker(ko_KR)`가 있으면 이를 사용하고, 없으면 내장 성·이름 조합으로 생성합니다.
- 성별은 현재 `F`, `M`을 동일 확률로 생성합니다.

연령 구간별 직업 확률은 생애주기상의 개연성을 반영한 합성 가정입니다. 직업은 최종 `users.csv`에는 출력하지 않지만, 요금제 지출 성향과 사용량 프로필을 만드는 내부 변수로 사용합니다.

### 2.2 가족 구조

전체 사용자의 약 56%가 가족에 속하도록 생성합니다. 내부 가족 형태는 핵가족, 한부모, 부부, 3세대, 형제자매, 성인 부모-자녀, 5인 확장가족을 가중치로 선택합니다.

| 가족 형태 | 구성원 수 | 추출 가중치 |
|---|---:|---:|
| `NUCLEAR_3` | 3 | 8% |
| `NUCLEAR_4` | 4 | 8% |
| `SINGLE_PARENT_2` | 2 | 4% |
| `COUPLE_2` | 2 | 26% |
| `THREE_GENERATION_3` | 3 | 4% |
| `SIBLINGS_2` | 2 | 18% |
| `ADULT_PARENT_CHILD_2` | 2 | 26% |
| `EXTENDED_5` | 5 | 6% |

목표 가족 사용자 수보다 큰 가족 형태는 후보에서 제외하고, 남은 후보의 가중치를 다시 정규화합니다.

가족 생성 시 다음 규칙을 검증합니다.

- 부모와 자녀의 최소 나이 차이는 18세입니다.
- 조부모와 손자녀의 최소 나이 차이는 36세입니다.
- 모든 가족 구성원은 같은 `family_id`를 가집니다.
- 최종 output에서는 가족 형태와 관계 행을 제거하고, `users.family_id`로 가족 구성원을 조회합니다.

정확한 부모·자녀 관계가 필요한 프리미엄 청소년 혜택은 내부 가족 역할을 사용해 생성하고 검증합니다. 다만 관계 데이터가 output에 없기 때문에 후보 요금제로 변경한 후 법정대리인 조건을 다시 판정하려면 분석 가정이 필요합니다.

### 2.3 사용량과 콘텐츠

사용자는 다음 잠재 일평균 데이터 프로필 중 하나를 가집니다.

| 프로필 | 일평균 기준 | 30일 환산 약값 | 목적 |
|---|---:|---:|---|
| `VERY_LOW` | 25MB | 0.7GB | 음성·초저용량 사용자 |
| `LOW` | 180MB | 5.3GB | 저용량 사용자 |
| `MEDIUM` | 700MB | 20.5GB | 일반 사용자 |
| `HIGH` | 2,000MB | 58.6GB | 고사용 사용자 |
| `VERY_HIGH` | 4,200MB | 123GB | 무제한 요금제 후보 |

연령별 사용량 프로필 추출 확률은 다음과 같습니다.

| 연령 | `VERY_LOW` | `LOW` | `MEDIUM` | `HIGH` | `VERY_HIGH` |
|---|---:|---:|---:|---:|---:|
| 8~12세 | 30% | 35% | 22% | 10% | 3% |
| 13~19세 | 8% | 17% | 32% | 28% | 15% |
| 20~39세 | 4% | 10% | 28% | 35% | 23% |
| 40~59세 | 6% | 18% | 36% | 27% | 13% |
| 60세 이상 | 18% | 32% | 31% | 15% | 4% |

13세 이상 학생·전문직·사무직은 `HIGH` 가중치를 1.15배, `VERY_HIGH`를 1.10배 높입니다. 은퇴·무직은 `VERY_LOW`를 1.15배, `LOW`를 1.10배 높인 뒤 전체를 다시 정규화합니다.

사용자의 대표 콘텐츠 성향은 연령별로 다음 확률에서 하나를 선택합니다. 이 값은 요금제와 초이스 혜택 선택의 보조 신호이며, 실제 일별 콘텐츠 비중과 동일한 값은 아닙니다.

| 연령 | 콘텐츠 성향 추출 확률 |
|---|---|
| 8~19세 | 영상 30%, 숏폼 28%, 게임 20%, SNS 12%, 음악 10% |
| 20~39세 | 영상 30%, SNS 20%, 음악 18%, 웹 12%, 숏폼 12%, 게임 8% |
| 40~59세 | 영상 28%, 웹 25%, 메신저 16%, 내비게이션 12%, SNS 10%, 음악 9% |
| 60세 이상 | 영상 26%, 메신저 28%, 웹 22%, 내비게이션 10%, 음악 7%, SNS 7% |

일별 사용량은 다음 순서로 생성합니다.

1. 사용자 잠재 일평균을 평균으로 하는 감마분포를 사용합니다.
2. 39세 이하는 주말 사용량을 14%, 그 외는 7% 높입니다.
3. 사용자별 로그정규 노이즈를 적용합니다.
4. 조정 전 일 사용 희망량을 5~25,000MB 범위로 제한합니다.
5. 유한 데이터 요금제는 월 누적 소진율에 따라 당일 관측 사용량을 줄입니다. 무제한 요금제는 이 조정을 적용하지 않습니다.
6. 이월 요금제는 직전 월 잔여량을 기본 제공량 한도 안에서 다음 달 사용 가능량에 더합니다.
7. 연령·직업·선택 서비스 성향을 반영한 디리클레 분포로 13개 콘텐츠 대분류에 배분합니다.
8. `video`, `short_form`, `music`, `ai`, `ebook`은 승인된 서비스 수준의 `content_detail`로 한 단계 더 분해합니다.
9. 반올림 잔차를 보정해 콘텐츠 합계가 내부 일별 총사용량과 정확히 일치하도록 합니다.

조정 전 일별 사용 희망량은 감마분포 `shape=3.2`, `scale=잠재 일평균÷3.2`를 사용합니다. 39세 이하는 주말에 1.14배, 40세 이상은 1.07배를 적용합니다. 사용자별 노이즈는 로그정규분포 `mean=0`, `sigma=0.16`에서 뽑아 0.70~1.45 범위로 제한합니다.

소진율은 달력 월 기준으로 누적합니다. 절약 반응 유형과 단계 진입 기준은 다음과 같습니다.

| 절약 반응 유형 | 사용자 비율 | `WATCH` 시작 | `SAVE` 시작 | `CRITICAL` 시작 |
|---|---:|---:|---:|---:|
| `EARLY` | 25% | 62% | 78% | 90% |
| `NORMAL` | 55% | 70% | 85% | 95% |
| `LATE` | 20% | 78% | 92% | 98% |

소진 단계에 따른 당일 총사용량 배수는 다음과 같습니다. 소진율 100% 이상은 반응 유형과 관계없이 `DEPLETED`로 처리합니다.

| 단계 | 총사용량 배수 |
|---|---:|
| `NORMAL` | 1.00 |
| `WATCH` | 0.95 |
| `SAVE` | 0.80 |
| `CRITICAL` | 0.55 |
| `DEPLETED` | 0.25 |

### 2.4 모바일 요금제 배정과 의도적 이상치

요금제 배정은 단순 무작위가 아니라 사용자와 요금제의 적합도 점수를 확률로 변환해 선택합니다.

주요 점수 신호는 다음과 같습니다.

- 월 데이터 필요량과 요금제 데이터 제공량의 적합성
- 직업에서 파생한 지출 성향과 월정액 거리
- 연령별 덤 혜택을 포함한 유효 데이터 제공량
- 콘텐츠 성향과 초이스 요금제 혜택의 적합성
- 가족 보유와 고가 요금제 사이의 약한 상관

사용자별 목표 월정액은 아래 식으로 계산합니다.

```text
목표 월정액
= 30,000
+ 25,000 × 직업별 지출 점수
+ min(40,000, 월 데이터 필요량GB × 300)
```

요금제 점수는 `-2.6 × |log(요금제 월정액) - log(목표 월정액)|`에서 시작해 아래 값을 가감합니다.

| 조건 | 점수 변화 |
|---|---:|
| 무제한, 월 필요량 80GB 이상 | +2.00 |
| 무제한, 월 필요량 40~80GB | +0.80 |
| 무제한, 월 필요량 10GB 미만 | -1.60 |
| 유한 요금제, 필요량÷유효 제공량 0.55~1.15 | +2.20 |
| 유한 요금제, 비율 0.25~0.55 | +0.90 |
| 유한 요금제, 비율 1.15~1.50 | -0.40 |
| 유한 요금제, 비율 1.50 초과 | -2.20 |
| 유한 요금제, 나머지 구간 | -0.80 |
| 음성 요금제이며 초저용량 조건 충족 | +1.20 |
| 음성 요금제이며 초저용량 조건 불충족 | -2.00 |
| 이월 요금제이며 필요량이 유효 제공량 미만 | +0.10 |
| 초이스 요금제이며 19~39세 | +0.30 |
| 초이스 요금제이며 영상·음악·숏폼 성향 | +0.50 |
| 초이스 요금제 지출 성향 | `+0.45 × 지출 점수` |
| 초이스 더블이며 지출 점수 0.70 이상/미만 | +0.15 / -0.15 |
| 베이직80·100이며 월 필요량 90GB 초과 | +0.45 |
| 가족이 있고 월정액 77,000원 이상 | +0.12 |

전체 요금제 점수는 softmax `temperature=0.78`로 확률화해 하나를 추출합니다. 따라서 조건이 같은 사용자도 항상 동일한 요금제를 받지는 않습니다.

기본적으로 사용자의 20%에는 추천 테스트를 위한 비최적 사례를 의도적으로 넣습니다.

| 내부 사례 | 의미 |
|---|---|
| `HIGH_USAGE_LOW_PLAN` | 데이터 사용량은 높지만 제공량이 부족한 요금제 |
| `LOW_USAGE_HIGH_PLAN` | 사용량은 낮지만 고가 요금제 |
| `VIDEO_NO_CHOICE` | 영상 사용 비중이 높지만 초이스 혜택이 없는 요금제 |
| `CHOICE_LOW_USAGE` | 초이스 혜택을 받고 있으나 관련 콘텐츠 활용도가 낮음 |

비최적 사용자 유형의 추출 가중치는 다음과 같습니다.

| 대상 | `HIGH_USAGE_LOW_PLAN` | `LOW_USAGE_HIGH_PLAN` | `VIDEO_NO_CHOICE` | `CHOICE_LOW_USAGE` |
|---|---:|---:|---:|---:|
| 13~18세 | 55% | - | 45% | - |
| 19세 이상 | 35% | 20% | 30% | 15% |

`HIGH_USAGE_LOW_PLAN`은 `VERY_HIGH` 사용량을 강제하고, 20%는 4GB 이하, 80%는 7~30GB 요금제에서 선택합니다. `VIDEO_NO_CHOICE`는 `HIGH`와 `VERY_HIGH`를 동일 확률로 선택하고 초이스가 아닌 요금제를 softmax `temperature=0.85`로 고릅니다. 고가·초이스 요금제를 고르는 비최적 사례는 최저 월정액과의 차이에 대해 `exp(-(월정액-최저 월정액)/20,000)` 가중치를 사용합니다.

이 내부 라벨은 분포 생성과 검증에는 사용하지만 최종 CSV에는 출력하지 않습니다.

### 2.5 연령 혜택과 선택 서비스

- 스쿨덤, Y덤, 65+덤, 75+덤은 사용자 나이와 요금제 조합으로 자동 적용합니다.
- 초이스·플러스·초이스 더블은 `plan_benefits`의 선택 가능 후보에서 실제 사용자 선택을 생성합니다.
- 초이스 더블은 후보 중 2개를 선택합니다.
- 일부 초이스 사용자는 혜택을 낮게 활용하도록 생성해 혜택 변경 추천 사례를 만듭니다.
- 사용자의 실제 선택은 `user_services`, 선택 가능한 전체 후보와 고정 혜택은 `plan_benefits`에 저장합니다.

초이스 후보의 기본 가중치는 1.0입니다. 대표 콘텐츠 성향과 서비스 카테고리가 맞으면 아래 배수를 적용한 뒤 정규화해 선택합니다.

| 대표 콘텐츠 성향 | 서비스 카테고리 | 선택 가중치 배수 |
|---|---|---:|
| 영상 | 영상·영상음악 | 3.0 |
| 숏폼 | 영상·영상음악 | 1.8 |
| 음악 | 음악·영상음악 | 3.0 |
| 웹 | 전자책·AI | 1.7 |

일반 초이스는 기본 혜택 1개를 선택하고 요금제에 `PLUS` 후보가 있으면 중복되지 않는 1개를 추가합니다. 초이스 더블은 서로 다른 후보 2개를 가중 비복원 추출합니다. 초이스 가입자의 22%와 `CHOICE_LOW_USAGE`로 지정된 사용자는 저활용 사례가 됩니다.

### 2.6 인터넷과 가족결합

인터넷 상세 상품명과 실제 인터넷 이용료는 저장하지 않습니다. 할인표를 선택하는 두 그룹만 생성합니다.

| 인터넷 그룹 | 합성 가중치 | 의미 |
|---|---:|---|
| `BASIC_ESSENCE_PREMIUM` | 75% | 높은 할인표 그룹. 프리미엄 가족결합 가능 |
| `SLIM` | 25% | 낮은 할인표 그룹. 일반 인터넷-모바일 결합으로 계산 |

인터넷 약정기간은 12개월 10%, 24개월 20%, 36개월 70%로 생성합니다. 인터넷을 보유한 비결합 가족에는 활성 또는 정지 상태가 존재할 수 있습니다.

모바일 고가 회선 조건을 충족한 가족의 시나리오 가중치는 다음과 같습니다.

| 시나리오 | 가중치 | 의미 |
|---|---:|---|
| `OPTIMAL_ENROLLED` | 55% | 총액·정액 중 정책상 유리한 방식으로 가입 |
| `SUBOPTIMAL_ENROLLED` | 17% | 실제 금액 차이가 있을 때 불리한 방식으로 가입 |
| `INTERNET_ACTIVE_NOT_ENROLLED` | 16% | 인터넷은 활성이나 결합 미가입 |
| `INTERNET_INACTIVE` | 12% | 인터넷이 없거나 정지되어 결합 불가 |

일반 가족은 60% 확률로 활성 인터넷을 가지며, 활성 인터넷 가족의 결합 시나리오는 최적 가입 62%, 비최적 가입 18%, 미가입 20% 가중치를 사용합니다.

활성 인터넷이 아닌 가족도 35% 확률로 정지된 인터넷 회선을 보유하게 하며, 나머지는 인터넷 없음으로 둡니다. 총액결합의 할인 풀 배분 방식은 `EQUAL`과 `CONTRIBUTION`을 동일 확률로 선택합니다.

결합 정책 적용 방식:

- 일반 `INTERNET_MOBILE`은 참여 모바일 전부를 총액 또는 정액 방식으로 계산합니다.
- `PREMIUM_FAMILY`는 높은 인터넷 그룹과 월정액 77,000원 이상 모바일 2회선 이상 조건을 사용합니다.
- 프리미엄 베이스 회선과 77,000원 미만 회선은 `D001` 또는 `D002` 대상입니다.
- 베이스 외 77,000원 이상 회선은 `D003` 25% 대상입니다.
- 청소년 본인과 법정대리인의 5G·월정액 조건을 충족하면 `D004`를 추가합니다.
- 가족 인터넷 혜택 `D005`는 사용자 행이 아니라 `families.internet_benefit_discount_id`로 연결합니다.
- 총액결합의 모바일 합계에는 인터넷 이용료를 더하지 않습니다. 인터넷 그룹과 약정기간은 할인 규칙 선택 조건으로만 사용합니다.

### 2.7 할인금액의 저장 범위

최종 CSV에는 사용자별 할인금액, 예상 청구액, 잠재 할인금액을 저장하지 않습니다.

- `user_discounts`는 사용자가 받는 `D001~D004` 혜택 종류와 적용 기간만 저장합니다.
- `D005`는 가족 인터넷 회선에 한 번 적용되는 혜택입니다.
- 생성기는 검증용 내부 정답값 `current_total_discount_amount`를 계산하지만 CSV에 출력하지 않습니다.
- 내부 정답값은 사용자 모바일 할인 `D001~D004`만 포함하며 `D005`와 선택약정은 제외합니다.
- 가족 단위 최적화에서는 정책표를 이용해 `D001~D005` 전체와 총액·정액 방식을 다시 계산할 수 있습니다.

## 3. 생성 순서

```text
정책·마스터 생성
→ 가족 구조와 독립 사용자 생성
→ 직업·지출 성향·사용량 프로필 생성
→ 현재 모바일 요금제와 연령 혜택 배정
→ 선택 서비스 생성
→ 인터넷·가족결합 시나리오와 사용자 할인 혜택 생성
→ 내부 현재 모바일 할인액 계산
→ 월 누적 소진율을 반영한 90일 일별 사용량 생성
→ 콘텐츠 대분류·상세분류별 사용량 분해
→ PK/FK·정책·합계 검증
→ 최종 14개 CSV 저장
```

각 단계는 기본 시드에 서로 다른 오프셋을 사용하므로 같은 옵션으로 실행하면 재현 가능합니다.

## 4. 검증 기준

생성기 실행 중 다음 항목을 검증합니다.

- 사용자·가족·요금제·서비스·할인 테이블의 FK와 중복
- 가족 구성원 수와 내부 관계의 연령 조건
- 인터넷 상태, 상품군, 약정기간과 결합 종류의 일관성
- 프리미엄 베이스·추가 고가·청소년 회선 자격
- 총액·정액 할인 수혜자와 정책 구간의 일치
- 내부 `current_total_discount_amount`와 활성 사용자 혜택의 대응
- 사용자·일자별 콘텐츠 합계와 내부 일별 총사용량의 일치
- 연령 혜택과 초이스 서비스 선택 조건

`scripts/check_distribution.py`는 저장된 output만 사용해 다음을 확인합니다.

- 14개 CSV의 필수 컬럼과 내부 전용 컬럼 유출 여부
- 사용자·요금제·콘텐츠·가족결합 분포
- 가족결합 적격·미가입·인터넷 정지 사례
- 총액·정액 중 정책상 비최적 방식을 선택한 가족 비율
- output 테이블의 주요 PK/FK와 결합 구성 정합성
